### T1：P52-D.1 — 后端 offset + count

#### `src/multiscribe_agent/core/publish_history.py`

**`query()` 方法加 `offset` 参数**：

```python
async def query(
    self,
    db: Database,
    publisher_id: str | None = None,
    from_date: datetime | None = None,
    to_date: datetime | None = None,
    limit: int = 50,
    offset: int = 0,                            # 新增
    digest_date: str | None = None,
) -> list[PublishRecord]:
    # ...filter 构建保持不变...
    statement = f"""
        SELECT id, publisher_id, status, title, content_preview, result_data,
               error_message, published_at, adapter_name, digest_date
        FROM {_TABLE_NAME}
        WHERE {where_clause}
        ORDER BY published_at DESC, id DESC
        LIMIT ? OFFSET ?
    """
    parameters.append(max(1, min(limit, _MAX_QUERY_LIMIT)))
    parameters.append(max(0, offset))           # 新增
    rows = await self._fetchall(db, statement, parameters)
    return [_record_from_row(row) for row in rows]
```

**新增 `count()` 方法**（独立函数，复用 filter 构建）：

```python
async def count(
    self,
    db: Database,
    publisher_id: str | None = None,
    from_date: datetime | None = None,
    to_date: datetime | None = None,
    digest_date: str | None = None,
) -> int:
    """Return the total number of records matching the given filters."""
    # 复用 query() 的 filter 构建逻辑
    filters, parameters = _build_filters(
        publisher_id=publisher_id,
        from_date=from_date,
        to_date=to_date,
        digest_date=digest_date,
    )
    where_clause = " AND ".join(filters) if filters else "1 = 1"
    row = await db.fetchone(
        f"SELECT COUNT(*) FROM {_TABLE_NAME} WHERE {where_clause}",
        parameters,
    )
    return int(row[0]) if row else 0
```

> **注**：filter 构建目前在 `query()` 内联，需要**提取**到 `_build_filters()` 私有函数（DRY）。Codex 需要重构这一步。

#### `src/multiscribe_agent/api/routes/publish_history.py`

**路由加 `offset` + 返回结构化对象**：

```python
@router.get("")
async def list_publish_history(
    publisher_id: str | None = None,
    from_date: datetime | None = None,
    to_date: datetime | None = None,
    limit: int = Query(default=50, ge=1, le=200),
    offset: int = Query(default=0, ge=0),       # 新增
    context: ServiceContext = Depends(get_context),
) -> dict[str, object]:                          # 改为 dict
    if context.db is None or context.publish_history is None:
        raise HTTPException(status_code=503, detail="services unavailable")
    
    total = await context.publish_history.count(
        context.db,
        publisher_id=publisher_id,
        from_date=from_date,
        to_date=to_date,
    )
    records = await context.publish_history.query(
        context.db,
        publisher_id=publisher_id,
        from_date=from_date,
        to_date=to_date,
        limit=limit,
        offset=offset,
    )
    return {
        "records": [_record_to_response(record) for record in records],
        "total": total,
        "limit": limit,
        "offset": offset,
        "has_more": offset + len(records) < total,
    }
```

#### `frontend/src/shared/ui.tsx` — PublishingPage

**新增状态 + 分页 UI**：

```tsx
import { ChevronLeft, ChevronRight, Send } from 'lucide-react'  // 加 ChevronLeft/Right

function PublishingPage(): ReactElement {
  const [offset, setOffset] = useState(0)
  const limit = 50
  const loadPage = useCallback(
    () => publishHistoryApi.list({ limit, offset }),
    [offset]
  )
  const remote = useRemoteData(loadPage)
  const status = DataStatus({ remote, empty: (remote.data?.records.length ?? 0) === 0 })
  if (status) return status
  
  const records = remote.data?.records ?? []
  const total = remote.data?.total ?? 0
  const hasMore = remote.data?.has_more ?? false
  const currentPage = Math.floor(offset / limit) + 1
  const totalPages = total === 0 ? 1 : Math.ceil(total / limit)
  
  return (
    <section className="data-panel">
      <div className="data-summary">
        <Send />
        <span>投递记录 第 {currentPage} / {totalPages} 页（共 {total} 条）</span>
      </div>
      <div className="data-list">
        {records.map((record: PublishHistoryRecord) => (...原有渲染逻辑...))}
      </div>
      <div className="pagination-row">
        <button
          type="button"
          className="button compact"
          disabled={offset === 0}
          onClick={() => setOffset((o) => Math.max(0, o - limit))}
        >
          <ChevronLeft size={16} />上一页
        </button>
        <span className="pagination-info">第 {currentPage} / {totalPages} 页</span>
        <button
          type="button"
          className="button compact blue"
          disabled={!hasMore}
          onClick={() => setOffset((o) => o + limit)}
        >
          下一页<ChevronRight size={16} />
        </button>
      </div>
    </section>
  )
}
```

**原代码的 `records.map` 改为 `remote.data?.records.map`** + 改用上面 `records` 变量。

## 八、风险与取舍

1. **offset + limit vs cursor**：用 offset 实现最简单。当发布历史累积到万级时 cursor 更好（避免大 offset 性能下降），但当前量级 offset 足够。
2. **total count 性能**：count() 与主查询 filter 一致，SQLite/Postgres 都走索引优化。count(*) 在 publish_history 表（通常几千行）毫秒级。
3. **API 签名向后兼容**：`list({ limit?, offset? })` 可选参数，原 `publishHistoryApi.list()` 无参仍有效。
4. **空态处理**：`total === 0` 时 `totalPages = 1`（避免 0/0 = NaN），按钮全部 disabled。
5. **filter 复用重构**：`query()` 内部的 filter 构建需提取到 `_build_filters()` 私有函数，**这是 P52-D 必须做的重构**（如果不做，count() 与 query() 的 filter 逻辑会重复，将来易错）。Codex 应在 `core/publish_history.py` 内部重构，**不暴露到外部 API**。
6. **既有页面 0 回归**：`publishHistoryApi.list()` 无参调用仍返回 `PublishHistoryResponse`，`records` 字段替代原数组。**Codex 需要在执行前确认前端所有 `publishHistoryApi.list` 调用点都做适配**（grep 应只命中 1 处：PublishingPage）。
